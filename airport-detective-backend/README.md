# YOLOv10 真实视频识别 Demo

## 接驳车 04 四路接入版

本副本已接入同级 `airport-detective-frontend`。通过上级目录 `start-monitor.cmd` 统一启动，根地址展示机场前端，`/workbench` 保留原算法工作台。四路调度与接口位于 `live_monitor.py`，详见上级 `README-四路接入.md`。四路监控期间原单视频任务不能同时启动。

当前停止操作保留任务档案和照片；清理照片使用独立的档案清理接口。以下旧版使用说明中的“停止并删除”描述不适用于当前副本。

## 启动和演示

双击 `start.cmd`，等待控制台出现访问地址并自动打开浏览器。默认 `http://127.0.0.1:5180`，若端口被占用会尝试后续 9 个端口。保持控制台运行，关闭控制台即停止服务。

1. 点击或拖入视频（最多 2 GB），等待导入检查完成。
2. 也可把任意视频复制到本目录 `videos/`，在页面刷新并选择；此方式无需再次复制上传，支持超过 2 GB 的文件。
3. 左栏最上方可填写当前车次、线路、车厢与摄像头。推荐先选 `yolov10n`、自动 GPU、识别尺寸 640、阈值 0.25、每帧识别，然后点击“开始智能研判”。
4. 放大的左栏实时显示检测画面和稳定编号；中栏每行列出一个行李候选；选择候选后，右栏显示最多三名可能所属人的照片与关联分数。这是按处理速度更新的预览，不承诺与视频播放速度同步。
5. 检测期间，页面下方“包裹证据档案”按包裹编号逐行累计保存。每行固定显示包裹照片、检测时间、研判状态，以及所有已关联人员的照片和最高关联概率，不随当前视频帧切换而消失。
6. 档案记录与关联概率持续写入 `data/jobs/<任务编号>/archive.json`，包裹照片保存在 `crops/`，人员照片保存在 `people/`。页面从本地档案接口读取；刷新浏览器或重启服务后仍可展示。
7. 点击“停止检测并删除结果”后，先关闭检测和视频文件，再删除本次任务生成的档案、照片、检测日志、报告和结果视频。正常完成时保留本地结果，仍可点击“停止并删除本地结果”清理。原始导入视频保留，仅保留最小任务状态用于标识已清理。
8. 预警指标按包裹编号累计去重：模型判为疑似遗留后计入黄色“疑似遗留”，离开画面仍保留。点击指标展示包裹图片，点击图片跳转并高亮对应档案行。核实后点击图片下的“确认遗留”转入红色指标，可撤销确认；确认状态保存到本地，不随实时推理变化。同一包裹仅属于一个预警分类，停止清理后计数归零。

## 持续运行与照片修复

实时预览只保留一个加载请求，8 秒超时后重试，等待期间显示上一张已解码画面。档案约每 2 秒更新，复用已加载照片，固定照片使用浏览器缓存。截图采用先编码、原子发布的写入方式，写入失败会明确报告，支持中文路径和四位及以上跟踪编号。

历史任务缺失照片时，在新版目录执行 `.venv\Scripts\python.exe repair_photos.py <任务编号>`。工具从该任务原视频和 `frames.jsonl` 补回缺失照片，无需重跑模型。只能修复已结束且尚未清理的任务，原视频必须仍在。停止时已删除的档案需重新检测建立。

持续运行验证命令：`.venv\Scripts\python.exe tests\soak_pipeline.py`。使用隔离的 2,000 帧真实视频，连续读取预览和所有档案照片，验证解码与接口响应。

附带 `videos/sample-carriage.mp4` 是旧项目 `0750-demo.mp4` 从第 2 秒截取的 8 秒真实车厢视频，可直接试用。旧版全部保存在同级 `demo-legacy/`。

## 功能与统计定义

- 六个用户提供的原始模型：YOLOv10n/s/m/b/l/x。模型越大通常计算量和显存需求越高。
- “全部 80 类”使用 COCO 类别；“人员与行李”只保留 person、backpack、handbag、suitcase 四类。
- 系统为检测到的人和行李建立跨帧编号。行李静止达到界面阈值，且没有稳定的近邻所属人时，标为“疑似遗留”；证据不足时标为“持续观察”；人与物稳定近邻时标为“随身携带”。
- 后端通过 `/api/jobs/<任务编号>/archive` 提供独立累计档案数据，便于调试包裹、人员和关联概率，不依赖实时画面当前帧。
- 所属人关联分数综合近邻距离、共同出现比例、当前距离和人员是否仍在画面。分数用于演示排序，没有经过概率校准，也不代表身份确认。
- 当前帧数量是该次分析帧中的框数；类别统计为每类单帧最高框数；出现帧数和累计框次数写入报告。均不进行跨帧去重。
- 输出 `result.mp4` 为浏览器兼容的 H.264，无原音频，保持画面比例，长边最多 1280 像素（编码时尺寸取偶数）。
- 默认每帧识别。抽帧模式只输出实际分析的帧，输出帧率为原帧率 / 间隔，时长基本保持，末尾最多一个采样间隔误差；会遗漏未分析帧中的短暂事件。
- 识别尺寸指模型输入尺寸；CSV / JSON 坐标基于输出画面的宽高，每条记录注明坐标尺寸。
- 视频时间戳按解码帧号 / 帧率估算；可变帧率视频建议先转为恒定帧率 MP4。检测结果不用于音频或完整自然语言视频理解。
- YOLOv10 只提供目标检测；跨帧编号、物主关联和遗留状态来自 `analytics.py` 的启发式规则。它不做人脸识别或身份认证。COCO 预训练模型对拥挤车厢、遮挡、小行李可能漏检或误检，跟踪编号也可能因遮挡而切换。

## 文件结构

```text
demo-yolov10/
  start.cmd / launch.ps1    双击启动入口
  app.py                   本机 HTTP API、上传、异步任务、MP4 与报告导出
  engine.py                原版 YOLOv10 本地加载和推理
  analytics.py             跨帧编号、行李状态与所属人关联规则
  static/                  中文工作台
  models/                  六个原始 .pt 模型副本
  vendor/ultralytics/       用户下载的 YOLOv10 分支代码副本
  vendor/LICENSE           原代码许可证
  videos/                  手动放入的视频及示例
  data/uploads/            浏览器上传的视频副本
  data/jobs/<任务编号>/     标注 MP4、报告、CSV、逐帧 JSON、状态
  data/server.log          服务与错误日志
  .venv/                   新版专用运行环境
  tests/                   API 与真实视频流程验证
```

数据不会上传到第三方。服务仅监听 `127.0.0.1`，用于本机单人演示；一次执行一个识别任务。任务与上传文件不会自动删除，以便回看。空间不足时先停止服务，再手动清理 `data/uploads/` 和 `data/jobs/` 内不需要的目录；仅删除结果并不会删除 `videos/` 中的原视频。处理中会临时生成 MJPEG 视频，长视频请预留足够磁盘空间。

## 当前机器环境

新版 `.venv` 通过 `--system-site-packages` 只读复用 `D:\Anaconda\envs\Experiment1` 的 Python 3.10.18、PyTorch 2.8.0+cu129、TorchVision 0.23.0+cu129 和 OpenCV 4.12.0；新增依赖仅装在新版 `.venv` 中，不修改旧环境。使用 NVIDIA GeForce RTX 5060 执行实际推理，无 GPU 时可选择 CPU。

因此当前 `.venv` 依赖这台机器的上述 Anaconda 环境；移动到其他电脑需要重建。不要直接安装用户源码里较旧的 `torch==2.0.1` 来覆盖当前环境，也不要安装 PyPI 的另一版 `ultralytics` 替换 `vendor` 源码。

旧 YOLOv10 权重是包含网络对象的完整 checkpoint。`engine.py` 仅在加载 `models/` 中白名单模型时，临时启用兼容 PyTorch 2.6+ 的完整 checkpoint 加载，再恢复环境变量；前端只接受视频，不接受上传权重。仅使用可信模型。

## 重建环境

本机需要重建时，可从同一个基础环境创建虚拟环境，然后用 **pip** 安装缺失依赖（pip 会识别已复用的 torch，避免无意覆盖 GPU 版本）：

```powershell
& 'D:\Anaconda\envs\Experiment1\python.exe' -m venv --system-site-packages .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py --open
```

其他电脑先用 Python 3.10/3.11 建立普通虚拟环境，安装适合该电脑的配套 PyTorch / TorchVision，再安装 `requirements.txt`。CPU 环境或不同显卡不要直接照搬本机 CUDA 版本。安装依赖需要联网，完成后识别使用本地代码、模型和视频。

## 排查

- 页面未打开：查看控制台显示的实际端口，手动访问；关闭重复运行的启动窗口。
- 视频无法导入：确认视频完整且扩展名支持；可先转为 H.264 MP4。浏览器不能播放某种源编码时，仍可由 OpenCV 解码并识别。
- 显存不足：使用 YOLOv10n、320 或 640 尺寸，或者切换 CPU。
- 没有检出行李：先用“全部类别”检查，降低置信度阈值或尝试 s/m 模型；阈值降低也可能增加误检。
- 服务重启：未完成任务会标记“已中断”，不会假装完成；需要重新开始。
- 详细错误位于 `data/server.log`，MP4 编码日志位于对应任务的 `encode.log`。
